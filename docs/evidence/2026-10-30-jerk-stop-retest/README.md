# 启动即停复测：斜坡已修复，根因是编码器供电线脱落（2026-10-30）

## 结论（用户现场确认）

用户最终确认：**编码器 3.3 V 电源线脱落**。这解释了本目录及前一次快照中两轮编码器计数全程为 0、
`distance_cm=0`、实测轮速 0，而电机仍能“动一下”的现象：6 芯霍尔插头中电机线（1、6 脚）导通，
编码器供电（2 脚）断开，A/B 相无脉冲。固件看到“有目标、无反馈”，350 ms 后按设计判堵转停车。

## 本次快照（只读，未烧录/未操作电机）

STBY 低预检查后短暂停核读 SRAM 4096 B 并请求 resume，未读 Flash、未冻结看门狗、未核对固件一致性。
按 `read-time.elf` 解码，控制器与诊断两份 `stop_snapshot` 逐字段吻合，布局解释一致。

## 两个独立问题的区分

1. **软件（已修复）**：速度斜坡被位置曲线钳死，车辆无法加速、PWM 过低。该 bug 真实存在并已由
   回归 `test_final_leg_ramp` 证实（旧源码退出 134、修正后通过）。
2. **硬件（本次根因）**：编码器 3.3 V 电源线脱落导致计数为 0，堵转保护停车。与软件修复无关。

- 本次只读诊断、未烧录、未操作电机；软件修复的实车效果仍需在编码器接好后复测。
