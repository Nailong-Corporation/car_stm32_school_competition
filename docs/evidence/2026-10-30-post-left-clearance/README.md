# 2026-10-30 首弯左转后在线停车：离口去重

## 读取边界

用户授权通过已连接 ST-Link 读取，明确要求不检查固件一致性。
没有读取 Flash、复位、烧录、写运行变量或请求 START。
运行中批量 RAM 读取出现不可靠数据，已弃用，不作为证据。
之后使用 1000 kHz SWD 短暂停核，读取 SRAM `0x20000000` 起 4096 B，
传输约 63 ms，随后立即 resume 并关闭 OpenOCD；没有冻结看门狗。
日志记录该次目标电压约 3.224 V。

`ram.bin` 是停核读取原始数据。`decoded.txt` 依读取时本地 ELF 的符号和类型
离线解码；`layout.txt` 保存结构布局。未核对板上版本，因此解码结果以该布局适用为前提，
不声明固件一致性。当前变量与首次停车锁存快照需区分：停车之后仍继续采样，
当前航向、位置与里程不代表触发停车的一刻。

首弯出口已于 12080 ms 确认，进入 CLEARING 时转角约 -1.83537 rad，
灰度为 `0x08`；`turn_exit[0].handed_off=false`，尚未交接下一表项。
20 ms 转弯环形记录中，进入 CLEARING 后位置经过 +1、+3、+5、+7；
停车时又在 -3。该环形记录不是完整的逐帧灰度历史。

按本地源码规则，480 ms 未达到 1500 ms 离口超时，而 20.0658 cm 已超过
`JUNCTION_CLEAR_MAX_CM=20`，所以这里的通用 `ACTION_TIMEOUT` 表示离口超距。
旧 CLEARING 要求每帧 `|position|<=2`，有效单线横移至 ±3 就会清空候选。
这些证据和源码共同定位到离口去重无法完成，而非第二项待直行路口已被错误消费。
没有完整传感器历史，不能还原每一次候选清空的具体原因，也不能把实测轮速当作理想跟随。

## 局部修正与回归

仅将 CLEARING 的线证据改为 `route_is_narrow_line()`：允许有效单一区域窄线在探头内横移。
原 3 帧、50 ms、2 cm 条件和 1500 ms / 20 cm 限界保留；无线、超宽、多区域、
采样中断仍清空连续证据。EXECUTING 的转角和连续中心出口线门禁不变。
不自动续跑、不跳段，不修改路径表、速度、极性、制动参数或 IMU 降级策略。

新增左右镜像回归覆盖中心到边缘横移、后续非目标路口直行去重、
无线/全目标/多区域与采样中断清空证据，以及独立离口超时和超距停车。
修正前新用例在无法推进到索引 1 的断言处失败，见 `regression-before.log`。
