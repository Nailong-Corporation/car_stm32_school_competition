# 元件处有界直行找线（2026-10-31）

用户反馈仍在元件上停止，明确要求遇此情况保持直走一段距离尝试找线。本次修改该行为策略，不重新读取ST-Link、不上传/复位或操作电机。上一轮元件停车的原始SRAM/旧ELF/20 ms轨迹仍在`../2026-10-31-component-stop/`，不以新ELF覆盖旧证据，不声称本次取得了新现场或确认板上版本。

## 行为

- 转弯EXECUTING须已经捕过线、相对转角至少目标95%，随后超宽/多区域才可开启一次恢复；转弯已确认出口的CLEARING及直行通过图形的CLEARING也可开启。仅无线、未捕线、转角不足不获得新预算。有效单一区域转弯线仍走原出口判定。
- 已证实的短中心走廊与新分支交接优先，避免恢复吞掉紧邻真实路口。恢复期间不计数、不推进路径项、不调整角度基准。
- 保持进入图形时的当前航向；直行过口保持原入口航向。冻结位置PID，航向误差与角速度反馈产生差速；外轮上限min(turn_speed,16 cm/s)，轮目标非负。IMU失败仍按既有连续编码器航向降级。
- 一次最多12 cm或1200 ms，任一先到停车EXIT_RECAPTURE=8；预算固定，不由噪声/原因切换刷新。旧400 ms/8 cm仅在明确进入该有界恢复期间由此预算接管；在旧期限已经到达时不能迟到开启恢复。
- 连续3帧单区域至多3路且居中才恢复原流程；侧边、宽线、多区域、孤立中心帧和采样中断不算恢复。自定义角仍保留角度及出口确认；恢复本身不宣告动作完成。
- 每个动作/过口一次机会，找到线后再次失效不能重新开启同一预算；正常完成动作离口或人工START后重建。转弯总时限、离口1500 ms/20 cm、错向/过转、速度/编码器/调度/俯仰停车不放宽，不自动恢复STOPPED。
- 离口已具备连续可靠居中出口时保留这份中心历史，避免恢复新增的确认过程造成下一图形前额外三帧等待；不对非居中/无连续中心的离口建立虚假历史。

`COMPONENT_HOLD`在README状态图中表示原EXECUTING/CLEARING内部的子过程，不是新增RouteState枚举。调试有active/used、起始时刻/距离/航向；停车快照增加恢复年龄/距离，g_diagnostics保留活动标志。

## 验证

- 新增test_component_recovery：左右镜像、400 ms后继续保持航向、3帧中心恢复、普通与自定义角、直行与转弯离口、单次预算、孤立噪声/侧边不解锁、时间/距离截止帧优先停车、旧期限先到不复活、错向/过转/动作超时、健康IMU到编码器降级及编码器故障锁定。
- 修改前HEAD路口实现不能进入恢复，新用例首个活动标志断言失败，见regression-before.log（该基线的转弯出口丢失逻辑与本次修改前相同，不冒充上一轮未提交识别修改的完整源码快照）。
- 上次现场20 ms采样作为有缺口的输入回放：原9758 ms处现在应仍处于有界恢复，不凭图形完成转弯；在恢复1200 ms边界仍必须停车。没有插值伪造5 ms真实采样，也不将该回放视为实车成功证据。
- 原离口与直行回归按新授权更新：宽图形获得一次有界预算；不合格侧边仍不能作为恢复出口。完整测试/构建结果见同目录日志与exit文件。

所有数值为未实测初值。未验证元件真实长度、恢复航向是否对应正确出口、轮胎打滑和实际轮速响应；不保证一定找到正确线。未烧录，RAM布局有变化，后续读取使用当时ELF。
