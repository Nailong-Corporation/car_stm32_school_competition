# 元件处停车诊断与路口识别优化（2026-10-31）

用户要求先诊断元件处停车，再按候选分型、连续性和回放计划优化。诊断在所有源码修改和构建之前执行。

## 现场读取与解释边界

- 保存读取前本地 `read-time.elf`。ST-Link V2J48S7，目标电压约3.22 V。
- 沙箱内USB访问失败；首个扩展权限命令因缺少恢复运行步骤被自动审核拒绝，未执行。修正为显式resume并对读取异常使用catch后获准执行。
- 运行态预读没有返回可靠GPIO值，不使用。随后短暂停核，在GPIOB ODR=0x713、PB5/STBY低的条件下读取SRAM4096B，立即resume；无Flash读取、复位、烧录、冻结看门狗、控制变量写入或START/电机命令。
- `ram.core`仅为离线SRAM容器，不含CPU寄存器；GDB寄存器缺失警告正常。按本地ELF解码，两份128B `stop_snapshot`逐字节相等，当前状态/时基/灰度均自洽。未比较Flash，不证明板上二进制与本地源码完全一致。

该次不是CLEARING离口去重停车、堵转、反向反馈、90°角度不足或3000 ms动作超时。原始`clear_progress_cm`来自旧clear基准，在EXECUTING不代表本次离口进度，不能用它诊断离口超距。

20 ms循环轨迹`trace.csv`按时间排序：9273～9333 ms为0x01、position=-7；9353 ms为0x03、position=-6；9373 ms起为0x63→0xff→0xc7→0xc6→0xc4→0x44→0x64→0x6c→0x2c→0x28→0x29→0x39→0x3b等宽线/多区域。保存的采样没有连续居中窄出口。9358 ms为控制器最后合格捕线时刻，不由20 ms轨迹臆造其完整输入。最初捕获记录是9273 ms、转角约86.82°、左边缘0x01。

可以确认“捕线后合格出口持续缺失，400 ms保护按设计停车”。不能从短轨迹确认前面四次计数是否全部正确、元件对应哪一条真实线，也不能断言硬件阈值/探头位置或具体图形是物理根因。实测轮差未按请求产生反向修正也值得后续调查，不能仅凭目标值断言车辆已经纠正。

## 识别优化

1. 强候选（中心+侧分支）保留3帧/0.1 cm。弱候选（2～3路边缘L形、中心组至少2路的分离分支）改为4帧/0.15 cm。
2. 连续候选按左右分支交集保持身份，左→双侧→右不累加；相邻图形交接也检查侧别连续性。三块及以上分离区域拒绝。
3. 重叠窄线逐步横移到边缘锁存曲线证据，避免平滑偏移被当作边缘路口；稳定中心线后才解除。突现L形仍可参与弱确认。这是启发式，可能漏掉观测相同的真实L形，需实测。
4. 每周期128帧输入/候选记录，包含停车当帧并冻结；原始GPIO可经过真实极性/多数滤波回放。窗口仅覆盖640 ms，非完整行程日志，滤波首两帧与窗口前历史有依赖。
5. 原表、速度、极性、标定、IMU降级、出口捕获/完成规则、400 ms/8 cm及其他保护均保持。没有依据允许本次多区域图形直接结束转弯，不通过延时、补计或跳段消除停车。
