# 提前低速入弯与连续捕线

本轮用户指出应在发现路口后更早开始慢速转弯，并提高出口捕线稳定性。本轮只修改本地代码、测试和文档，没有再次连接 ST-Link、复位、烧录或操作电机；沿用前一次 [只读现场](../2026-11-02-left-exit-read/README.md)。原640 ms导航轨迹起点已在转弯中，不能量出从初次看见路口到实际开始差速的完整延迟，也不能据此确认轮子开始转弯时在赛道上的精确位置。

## 可确认的软件机制与现场限制

1. 此前表内入口上限50 cm/s、转弯目标慢速上限16 cm/s不一致。轮速反馈同时高于两轮目标时，速度环可能输出0/0；motor_apply 对双零输出选择 STBY 低待机，双轮滑行，不能当成内轮已刹住或车辆已产生转向。新主机用例验证这个软件输出路径；原轨迹没有保存路口入口每帧PWM，不能宣称已测出当时每帧都在滑行。
2. 原现场首次左边缘捕线时右轮反馈约39，中心出口确认后仍约33 cm/s，随后线从左扫到右再失去。只在开始转弯后降目标仍可能太晚；因此减速包络、候选目标、入口实测速度门禁和转弯动作统一使用 `v_entry=min(turn_speed,16)`。
3. 原 EXECUTING→CLEARING 会重置位置PID和速度PID，清零刚建立的横移微分及反向反馈候选；正常离口又不再叠加转弯角速度阻尼。新控制保留这两个控制器的历史，继续位置反馈和阻尼，避免在出口刚通过中心时丢掉趋势信息。
4. 原离口失线后锁住失线时航向，可能把已经偏离出口的方向当成新目标。现在在原400 ms/8 cm总限界内向已确认出口航向低速回正，仍须连续3帧有效线恢复；持续失线、动作/离口超时、错向/过转与反馈故障仍停车。未启用负PWM或自动短刹。

## 提前动作的边界

仅当前目标项为普通LEFT/RIGHT、近期有真实中心历史、连续同一单侧强中心+分支且与目标侧一致时，2帧且净前进0.05 cm即确认；通常强候选仍3帧/0.1 cm、弱边缘和分离图形4帧/0.15 cm。双侧桥接、跨侧、单帧、静止、采样中断、STOP/STRAIGHT/自定义角与非目标路口不使用提前规则。计数仍在真实确认后更新，距离不触发转向。以5 ms周期计，合格强候选理想可减少一个周期，不能推称已实测大幅提前或识别元件语义。

当前表内末段长度均0，无法知道准确制动点：启用入弯减速时，目标转弯的最终一段从入段就限制到不高于16 cm/s；已测量且合法的非零长度才使用距离包络，远处可恢复巡航。倒数第二口去重期间开始按该入口上限减速。关闭入弯减速开关不关闭实际入口门禁，若来不及减速可能停车；不以取消保护掩盖问题。表内速度、计数、机械尺寸和标定系数未改。

## 验证

- `pre-fix-test.log`、`pre-fix-evidence.log`、`pre-fix-history.log` 分别证明旧逻辑在入弯速度上限、目标强分支提前确认、捕线微分连续性三个用例上断言失败（退出134）。`before.elf` 为本轮改动前本地固件，不声称是板上版本。
- 新 `test_turn_handoff.c`：两极性、IMU开/关分别覆盖，含左右镜像、已测长度远处巡航/末端减速、实际入口超速门禁、弱/非目标/跨侧与中断拒绝、捕线横移微分、离口阻尼、原预算回正与持续失线停车、切换时反向反馈确认不被清空；开启IMU时另测真实IMU航向输入和当帧降级。定向用例IMU关/开分别508/518项检查，完整套件共65项PASS，退出0。记录见 `host-tests.log`、`host-tests.exit`。
- 部分历史测试原先给出40/50 cm/s反馈却期望直接转弯，已改为先验证BRAKING，再输入8 cm/s真实模拟计数使反馈降到16以下；速度开关矩阵继续验证关闭规划不关闭入口门禁。
- `test_closed_turns` 的旧合成传感器以单个角度阈值决定中心线，新增阻尼后略回转就人为瞬间失线。该用例现持续提供合成出口，仅验证控制器与FSM合作；横移/失线/恢复门禁由独立用例验证。它不是物理惯性、轮胎或传感器安装几何的模拟，不当成实车抓线证明。
- `pio run` 唯一环境构建成功，Flash 39408 B、静态RAM 10288 B；未增加控制器字段布局。`pio-run.log`、`pio-run.exit` 保存结果。README架构和状态Mermaid已同步。

尚须用新固件实测：真实入弯反馈是否在16以内、候选到轮差的延迟、24 cm前置探头首次捕线的位置、横移纠偏和实际停车。沿用的距离2.15/航向0.77系数仍需新轮标定；主机通过不能保证不再扫过或永不停车。
