用户反馈第二次转弯前没有减速冲出，首弯前太慢。本轮追问后用户确认：从第一弯离口到第二个左转，总共4个节点，保持路径表，重点修复漏计和速度。不能把计数4改3，也不能用距离代替缺失节点。

沿用ST-Link读取授权与“不检查固件一致性”要求。保存读取时本地read-time.elf，GPIOB ODR=0、PB5/STBY低才短暂停核读取SRAM16 KiB，随后resume/shutdown（openocd.log）。未复位、烧录、读Flash、冻结看门狗、写控制变量或请求START。ram.core仅为离线SRAM容器，无CPU寄存器。

## 修复

1. 新增计数采样速度上限JUNCTION_DETECTION_SPEED_CM_S=50。未进入末段的多节点FOLLOW/CANDIDATE及直行穿越，从一开始就取min(cruise,50,其他上限)，不等分支进入候选才从200开始降目标。保持航向修正时对两轮目标按比例限峰50，保留差速方向；限目标不等于保证真实轮速即时合格。该限制独立于入弯减速开关；路径关闭时不生效。
2. 原计数生命周期保持：确认第3个节点并完成离口后才建立最后70 cm起点，确认第4个才执行LEFT。原强/弱/同侧目标证据、去重和实际入口门禁不变。表内4以及其他节点数、速度、65/70/50/70长度均未改。
3. 首段的低巡航档单独微调：表内cruise<=50采用50 cm/s²规划，高巡航档仍40；不按当前反馈轮速反复换档。50→16名义减速距离22.44 cm，原40档为28.05 cm，约晚5.61 cm开始减速。固定margin+guard=5 cm、反馈滤波+一周期预留、60 cm原因13边界和16 cm/s真实入口门禁保持，不恢复120档、不启用反向力矩。50档仍为待实测初值。
4. 同步README总体数据流/状态Mermaid、导航文档和开关矩阵测试。RAM结构未变，快照仍176 B、轨迹64 B；历史现场继续使用读取时ELF。
