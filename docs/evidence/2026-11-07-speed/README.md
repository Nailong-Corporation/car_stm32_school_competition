## 0. 结论摘要

1. **负 PWM 反向制动可以在开关隔离下实现**，且关闭时行为与改前逐字节一致：默认 `MOTOR_REVERSE_BRAKE_ENABLED=0`、
   `BRAKING_REVERSE_HARDWARE_CONFIRMED=0`，副本 `node tests/replay.mjs 2` 的逐周期 CSV 与改动前基线 `diff` 完全相同。
2. **制动能力**：从 300 cm/s 刹到 16 cm/s，滑行需 163.5 cm / 1.35 s，短刹需 150.3 cm / 1.00 s，反向制动（模型取牵引极限
   600 cm/s²）只需 **75.3 cm / 0.52 s**；从 200 cm/s 刹到 16 cm/s 由 79.7 cm 降到 33.6 cm。反向制动把刹车距离大约减半。
3. 但**反向制动的收益完全取决于真实附着极限**：把模型牵引极限降到 300 cm/s²（0.3 g）时反向制动距离 150.1 cm，与短刹
   150.3 cm 基本相同——因为现有滑行/短刹模型已被 `MOTOR_MAX_DECEL_CM_S2=300` 钳住。只有真实附着 > 0.3 g，反向才有意义。
4. **方案 2 前 6 步在当前导航逻辑下跑不通提速**：同一条路线，只有 60 cm/s 巡航能走完前 6 步；70/80/90/100 cm/s 都在第 2–3 步
   失败，150/200 与 150 完全同轨迹（被 120 cm/s² 规划包络钳死）。失败不是“过弯太快”——每次转弯执行前实测轮速都被限制在
   13.8–16.8 cm/s。
5. 失败根因是**路口计数/授权对速度极其敏感**：现有证据窗口是距离型的（中心记忆 1.5 cm、前进量 0.1 cm、100 ms 超时），
   3 帧证据在 75 cm/s 时占 1.125 cm（勉强），在 100 cm/s 时正好 1.5 cm，≥100 cm/s 就散架。同一处印刷元件图形在 60 cm/s
   会计数、70 cm/s 不计、80 cm/s 又会计数且多出一个弱边，导致目标路口授权提前或滞后 20–100 cm。
6. 因此**给 Lead 的建议顺序**：先让路口证据窗口随速度自适应（Lead 正在改的导航部分），再谈提速；反向制动作为高速进弯的
   最后一道保险，单独开宏、等架空/低速标定后再启用，不要用它来弥补证据窗口。

## 2. 实现（开关隔离的最小改动）

### 2.1 开关（与固件同名同义）

| 开关 | 默认 | 作用 |
|---|---|---|
| `MOTOR_REVERSE_BRAKE_ENABLED` | 0 | 速度内环允许在“制动请求”下输出受限负 PWM（固件同名宏已存在，默认 0） |
| `BRAKING_REVERSE_HARDWARE_CONFIRMED` | 0 | 导航层允许武装反向制动（固件同名宏已存在，默认 0） |
| `REVERSE_BRAKE_MAX_PWM` | 60 | 负 PWM 幅值上限（255 标尺） |
| `REVERSE_BRAKE_MARGIN_CM_S` | 3.0 | 实测高于目标 3 cm/s 才施加反向力矩 |
| `BRAKING_REVERSE_MIN_SPEED_CM_S` | 8.0 | 低于 8 cm/s 切断反向输出，禁止倒车 |
| `BRAKING_REVERSE_MAX_MS` | 250 | 每段累计反向力矩时间上限 |
| `BRAKING_REVERSE_GUARD_CM` | 3.0 | 规划/判定用的距离余量 |

仿真侧这两个开关可用环境变量翻转（只影响 node 实验；浏览器构建里没有 `process`，保持默认 0）：
`SIM_MOTOR_REVERSE_BRAKE=1 SIM_BRAKING_REVERSE_HW=1`。其余实验期可调模型参数同理：
`SIM_REVERSE_MAX_DECEL_CM_S2`、`SIM_REVERSE_TORQUE_FULL_CM_S2`。

### 2.2 改动要点

- `speed_control.ts`：`update()` 增加可选 `reverse_brake` 参数；仅当开关为 1、该帧被授权、且
  `measured > 8` 与 `measured > target + 3` 时，用同一个速度 PID 在 `[-60, 0]` 区间算负 PWM。
  **速度目标始终非负**，负值只表示“反向力矩”，不是倒车目标；`target == 0` 仍直接输出 0（零输出=滑行语义不变）。
  命令仍以“幅值 + 方向标志”表达：`left_pwm = |pwm|, left_forward = pwm >= 0`。
- `physics.ts`：`advanceWheel()` 增加负占空比分支，使用**独立**的减速力矩模型
  （牵引极限 600 cm/s²、力矩随占空比线性上升、`speed` 永不为负）；关闭开关时负占空比退化为短刹。
  原 `MOTOR_COAST_TAU_S=0.35` / `MOTOR_BRAKE_TAU_S=0.08` 零输出模型不动。
- `line_follow.ts`（单独一个补丁）：把固件 `line_follow.c` 已有的武装逻辑移植过来——观测减速度低通 →
  `brakingDecide()` 判定“被动减速不足” → `narrow && stable && FOLLOW && 双轮实测 > 8 cm/s && 累计 < 250 ms`
  才允许、且只消耗 `state==LINE_TRACKING && narrow` 帧的预算。默认开关下这些代码路径不生效。

### 2.3 与固件的关系

**固件 C 端其实已经写好了这项功能**（`motion_config.h` 的 `MOTOR_REVERSE_BRAKE_ENABLED`、
`BRAKING_REVERSE_HARDWARE_CONFIRMED`、`BRAKING_REVERSE_MAX_MS/GUARD/MIN_SPEED`，速度环
`speed_control.c` 的负 PWM 分支，`motor.c` 的方向/限幅，`line_follow.c` 的武装逻辑），只是两个开关默认 0。
本补丁是**把这套逻辑补进仿真器**，让 Lead 可以在不碰硬件的情况下先测参数。C 端能直接落地，见第 7 节。

### 2.4 补丁

- `reverse-brake.diff`：`config.ts`、`speed_control.ts`、`physics.ts`（任务要求的核心三文件）
- `reverse-brake-route-hook.diff`：`line_follow.ts` 接线（因用户要求核心 diff 只含三文件，单独存放；不含它则仿真路线不会武装反向制动）

## 5. 失败点诊断（为什么提速失败）

回放事件（`summaries/*.events.jsonl`）里位置是**车轴里程点**，灰度杆在车轴前方 24 cm：

| 巡航 | 结果 | 事件证据 |

| 80 rev0 | 第 2 步失败 | (55.8, 29.7) 计 1 后，(55.4, 38.5) mask=0x0E 的**弱边**又被计 2 → 在 y≈39–51 提前约 90–100 cm 起转 → `EXIT_LOST` |

**证据窗口算术**：`JUNCTION_CONFIRM_SAMPLES=3`、控制周期 5 ms → 3 帧 = 15 ms。`JUNCTION_CENTER_MEMORY_CM=1.5` 要求这 3 帧
落在 1.5 cm 内 → 速度上限 1.5 cm / 0.015 s = **100 cm/s**。60–75 cm/s 时 1.125 cm 仍有余量；100 cm/s 正好临界；≥100 cm/s
必然失配，这正是 100/150 失败、而入口轮速仍只有 13–17 cm/s 的原因。

**反向制动的副作用**：反向制动会改变到达节点的**时刻/里程**，而当前计数与“枢轴接近距离 17 cm”都依赖里程，
所以即使总制动距离变短，也可能让目标路口提前/延后授权（60 cm/s 时第 5 步偏 31 cm）。这说明反向制动**不能单独提速**，
必须和路口证据、枢轴时序一起标定。

## 7. 给 Lead 的落地建议（C 固件）

### 7.1 直接可用的宏（C 端代码已经完整）

```c
/* include/motion_config.h —— 仿真已在同样参数下验证逻辑可跑 */
#define MOTOR_REVERSE_BRAKE_ENABLED        1   /* 速度环允许负 PWM（幅值上限 60） */
#define BRAKING_REVERSE_HARDWARE_CONFIRMED 1   /* 导航层允许武装；必须先做架空/低速真值表验证 */
/* 以下建议保持初值 */
#define REVERSE_BRAKE_MAX_PWM              60.0f
#define REVERSE_BRAKE_MARGIN_CM_S           3.0f
#define BRAKING_REVERSE_MIN_SPEED_CM_S      8.0f
#define BRAKING_REVERSE_GUARD_CM            3.0f
```

只开 `MOTOR_REVERSE_BRAKE_ENABLED`、不开 `BRAKING_REVERSE_HARDWARE_CONFIRMED` 时，速度环永远收不到
`reverse_brake=true`，等于只装接口不启用，可先这样上板验证“没有回归”。

### 7.2 建议调参（仿真依据）

1. `BRAKING_REVERSE_MAX_MS` 250 → **400**（若继续提高巡航）：600 cm/s² 下 250 ms 只能带走 150 cm/s，从 300 cm/s 起步
   到不了 16 cm/s 入口。按 `ms ≈ (v-16)/0.6` 估算，300 cm/s 约需 475 ms。
2. 建议**新增**一个武装速度门限（仿真里没有，但建议 C 端加）：`REVERSE_BRAKE_ARM_MIN_SPEED_CM_S ≈ 90`，
   或把武装条件从 `required_decel > safe_decel` 改成 `required_decel > 1.5 × safe_decel`。原因：`braking_decide()`
   用的是低通后的观测减速度，滤波滞后会让 60 cm/s 巡航也攒满 250 ms 反向预算（第 5 节 rev1 实测 1010 ms/4 段），
   白白扰动节点时序。
3. `BRAKING_SAFE_DECEL_CM_S2` 120 → **250**：仅当反向制动确认可用后再提；物理能力（滑行/短刹 300、反向 600）仍有
   1.2–2.4 倍余量。提高它能让长段跑更快（第 4 节 150/200 被 120 钳死的根因）。
4. 顺序建议：**先修路口证据窗口（Lead 正在改的导航）+ 巡线/图形通过速度，再提巡航，最后开反向制动**。

### 7.3 风险（必须在实车/架空上确认，不能只靠仿真）

- **反向保护误触发**：`SPEED_FAULT_REVERSE` 在实测 < -0.5 cm/s 持续 50 ms 或累计 0.1 cm 时停车。硬反向制动若造成
  短暂倒转/打滑回退，会直接锁死停车。`MIN_SPEED=8` 已留余量，但需架空验证。
- **固定 23% 占空比在高转速下力矩不足**：反电动势随转速上升，高速时同样的 60/255 占空比制动转矩会显著下降，
  第 3 节 600 cm/s² 是模型假设，必须实测定“速度—减速度”曲线。
- **电气/机械**：反向电流尖峰、电池压降、TB6612 发热、轮系冲击；建议先在架空、低速（≤100 cm/s）验证方向真值表
  （`motor_short_brake()` 与反向是两种不同的硬件状态，勿混）。
- **节点时序偏移**：本报告已证明反向制动会移动节点确认里程（60 cm/s 时 31 cm），启用后必须重新标定
  `TURN_PIVOT_APPROACH_CM` 与计数窗口，否则会在拐角前/后起转。
- **5 m/s 不可直接使用**：190 cm 段从 500 刹到 16 需 657 cm/s²，超出模型；赛道上限由段长决定。

## 8. 局限

1. **仅仿真**：`MOTOR_MAX_DECEL_CM_S2=300`、`MOTOR_REVERSE_MAX_DECEL_CM_S2=600`、`MOTOR_REVERSE_TORQUE_FULL_CM_S2=2550`
   都是本报告引入/沿用的模型假设，**不是实测标定值**；未烧录、未操作硬件。
2. **快照**：路线级结论基于 2026-11-06 22:08 的仿真器快照；主树 22:20 被 Lead 并发修改（导航），新树上的路线行为
   本报告未重测。补丁已按当前主树重生成并验证可应用/可编译。
3. **方案 2 本身不完整**：基线（60 cm/s、反向关）也只能走到第 9 步（约 982 cm）就 `EXIT_LOST`，所以“前 6 步”之外
   没有可信结论；第 4、5 节的差异里有一部分来自路线本身对节点计数的脆弱性，不全是速度造成。
4. 峰值减速度受编码器量化 + 30 ms 速度滤波影响，比模型值偏高/抖动，只作量级参考。
5. 反向制动的“停机”语义：`target==0` 时速度环不施加反向力矩，因此反向是进弯调速手段，不是驻车刹车。
